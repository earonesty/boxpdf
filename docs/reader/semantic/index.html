Visual and semantic profiles

Semantic structure is inferred from page geometry.

Adjacent text can belong to different columns, while separated text can belong to one sentence. The semantic pass uses coordinates, alignment, spacing, and repeated page elements to group content.

visual

Positioned output

Coordinates, baselines, font metrics, vectors, images, clipping, transforms, and paint order remain available.

semantic

Reflowable output

boxpdf infers text order and groups related content. It also detects tables, repeated headers and footers, sections, and tables continued across pages.

  • HTML reading order
  • Search and indexing
  • Structured extraction
Source coordinates are retained. Use them to locate semantic output on the original page and to inspect grouping errors.

Uses for semantic output

Reading order

Write positioned content as headings, paragraphs, lists, and tables using standard HTML elements.

Extraction pipelines

Process inferred paragraphs, fields, and tables while retaining page and bounding-box references.

Search and indexing

Index coherent blocks instead of isolated glyph runs, while preserving page and bounding-box provenance for every result.

Tables and forms

Infer rows, continued tables, totals, addresses, cards, labels, and values from their page positions.

Semantic API

Write semantic HTML with bounded lookahead.

import { blobSource, openPdf } from "@boxpdf/reader";
import { writeHtmlDocument } from "@boxpdf/html-writer";

const pdf = await openPdf(await blobSource(file));

await writeHtmlDocument(pdf.pages(), write, {
  profile: "semantic",
  semanticLookaheadPages: 4
});

semanticLookaheadPages controls how many pages may be buffered while detecting cross-page structure.
